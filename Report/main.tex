\section{Executive Summary}

This report covers how we designed, built, secured, automated, and monitored a department-level campus network for the Hapugala premises of the Faculty of Engineering, University of Ruhuna. Four departments sit on this network: Electrical \& Information Engineering (\textbf{DEIE}), Civil \& Environmental Engineering (\textbf{DCEE}), Mechanical \& Manufacturing Engineering (\textbf{DMME}), and Inter-Disciplinary Studies (\textbf{DIS}).

We built the network around Cisco's Three-Layer Hierarchical Model — core, distribution, and access — since it gave us the availability, segmentation, and manageability the brief called for. The one design decision worth calling out up front is moving the distribution layer away from plain Layer 2 trunking toward a \textbf{Layer 3 Multilayer Distribution} setup. Instead of trunking VLANs all the way back to the core, each distribution switch (\textbf{SW-D-DEIE}, \textbf{SW-D-DCEE}, \textbf{SW-D-DMME}) now terminates its own VLAN locally and connects to the core switch (\textbf{SW-CORE}) over routed \texttt{/30} point-to-point links running \textbf{OSPF Area 0}. That gets rid of Spanning Tree loops across the backbone, brings convergence down to well under a second, and makes better use of the available bandwidth.

Security between departments is handled with \textbf{extended named ACLs} applied inbound on the distribution SVIs and core interfaces. DEIE engineering workstations get full two-way access to the server farm; DCEE administrative staff can reach DIS over HTTP/HTTPS only, with ICMP blocked; DMME's workshop lab is walled off from every other academic subnet; and established TCP return traffic is allowed through while anything unsolicited from outside is dropped. We verified all of this with a full \textbf{\texorpdfstring{$4 \times 4$}{4x4} department reachability matrix}, backed by ping and traceroute captures plus ACL hit-counter output.

We also wanted to avoid hand-configuring seven switches and two routers every time something changed, so we built a \textbf{two-tier automation setup}:
\begin{enumerate}
    \item \textbf{Python + Netmiko} handles the routers (\textbf{R-CORE}, \textbf{R-EDGE}) — interface provisioning, OSPF, NAT, and pushing out SNMP community strings.
    \item \textbf{Ansible} (using the \texttt{cisco.ios} collection) handles the switches, with roles split out for \texttt{vlans}, \texttt{trunking}, \texttt{access\_ports}, \texttt{stp}, \texttt{l3\_distribution}, and \texttt{l2\_gateway}. We checked idempotency with \texttt{--check} and kept a rollback playbook on hand for all seven switches.
\end{enumerate}

For ongoing visibility we stood up \textbf{Zabbix 6.x LTS} on an Ubuntu VM (\textbf{VM-ZABBIX}). Every router and switch is polled over SNMPv2c using the stock Cisco templates, and we added triggers for ICMP outages, interface flaps, high CPU, and a custom check for management-plane splits. A dashboard (\texttt{FoE-UoR Network}) pulls it all together — link health, host status, and open alerts at a glance.

\subsubsection{Why We Moved the Distribution Layer to Layer 3}
We started out with the distribution switches acting as plain Layer 2 bridges, trunking VLANs 10, 20, 30, and 99 back to \textbf{SW-CORE}. That worked, but it came with problems we didn't want to live with long-term:
\begin{enumerate}
    \item \textbf{STP had to block redundant links}: Spanning Tree kept one of every pair of parallel links shut down to avoid loops, which meant paying for bandwidth we couldn't use — and if STP ever misbehaved, the whole campus was one broadcast storm away from trouble.
    \item \textbf{Inter-VLAN traffic took the long way round}: anything crossing VLANs had to hop over an L2 trunk to SW-CORE just to get routed, adding latency and loading up the backbone unnecessarily.
    \item \textbf{VLAN 99 got split up}: once we cut over the distribution uplinks to routed \texttt{/30} links, VLAN 99 stopped being one contiguous Layer 2 domain. We had to add explicit \texttt{/32} host routes on SW-CORE to keep management traffic reaching every node — more on that in Section~6.1.
\end{enumerate}

Once the default gateways (SVIs) moved down to \textbf{SW-D-DEIE}, \textbf{SW-D-DCEE}, and \textbf{SW-D-DMME}, Layer 2 broadcasts stayed local to each access switch instead of spreading across the backbone. The uplinks to SW-CORE became routed point-to-point links (\texttt{no switchport}), which opened the door to equal-cost multipath routing and OSPF reconvergence in well under a second.

\subsection{Routing Architecture \& NAT Overload}

\subsubsection{Open Shortest Path First (OSPF Area 0)}
We run single-area OSPF (\textbf{Area 0}) across every Layer 3 node.
\begin{itemize}
    \item \textbf{R-CORE} advertises the transit link \texttt{10.0.0.0/30} and the backbone link \texttt{10.0.1.0/30}.
    \item \textbf{SW-CORE} advertises the backbone link \texttt{10.0.1.0/30}, the three point-to-point links (\texttt{10.0.10.0/30}, \texttt{10.0.20.0/30}, \texttt{10.0.30.0/30}), the server farm network \texttt{10.10.40.0/24}, and the management subnet \texttt{10.99.99.0/24}.
    \item Each \textbf{distribution switch} advertises its own routed \texttt{/30} link plus its client SVI (\texttt{10.10.10.0/24}, \texttt{10.10.20.0/24}, or \texttt{10.10.30.0/24}).
\end{itemize}
We set \texttt{passive-interface default} on every OSPF process and then explicitly re-enable it only on the actual transit links, so client-facing SVIs can't accidentally form OSPF adjacencies with something they shouldn't.

\subsubsection{Static Default Routing \& Internet Egress}
\textbf{R-EDGE} carries a static default route out to the ISP cloud:
\begin{lstlisting}[style=ciscostyle]
ip route 0.0.0.0 0.0.0.0 FastEthernet0/0 203.0.113.1
\end{lstlisting}
\textbf{R-CORE} has its own static default pointing at \textbf{R-EDGE} (\texttt{10.0.0.1}), and we redistribute that into OSPF with \texttt{default-information originate} so SW-CORE and the distribution switches all learn a default route without us configuring it on each one individually.

\subsubsection{Network Address Translation (PAT) Policy}
\textbf{R-EDGE} does Port Address Translation (NAT overload) for internet access. Per Section 3.3 of the project brief, \textbf{only DEIE (VLAN 10) and DCEE (VLAN 20) get internet egress} — DMME (VLAN 30) and DIS (VLAN 40) are deliberately left out of the NAT pool.

\begin{lstlisting}[style=ciscostyle, caption={R-EDGE NAT ACL Configuration}]
! R-EDGE NAT ACL Configuration
ip access-list standard NAT_ALLOWED
 permit 10.10.10.0 0.0.0.255
 permit 10.10.20.0 0.0.0.255
 deny   ip any

ip nat inside source list NAT_ALLOWED interface FastEthernet0/0 overload

interface FastEthernet0/0
 ip nat outside

interface GigabitEthernet0/1
 ip nat inside
\end{lstlisting}

    \item \textbf{DMME Test Host}: \texttt{PC4} (\texttt{10.10.30.10/24}, Gateway: \texttt{10.10.30.1})

\section{Network Automation Framework}

\subsection{Python \& Netmiko Automation (Router \& SNMP Plane)}

We automated router provisioning and the SNMP community-string rollout with Python 3 scripts built on \textbf{Netmiko}.

\subsubsection{Architecture and Execution Flow}
The project is organized into a config file, a few functional scripts, and log output:
\begin{itemize}
    \item \texttt{inventory.yaml}: keeps credentials, IP addresses, secrets, and interface parameters out of the Python code.
    \item \texttt{01\_configure\_routers.py}: sets up interface addressing, enables OSPF, applies NAT overload, and configures the default static route on \textbf{R-CORE} and \textbf{R-EDGE}.
    \item \texttt{02\_configure\_snmp\_all.py}: pushes the SNMPv2c read-only community string (\texttt{public\_foe\_snmp}) and the trap server address (\texttt{10.10.40.100}) out to all 10 devices.
    \item \texttt{03\_verify\_config.py}: runs \texttt{show ip interface brief} and \texttt{show ip ospf neighbor} afterward to confirm nothing broke.
\end{itemize}

\begin{lstlisting}[style=pythonstyle, caption={Netmiko Router Automation Snippet}]
import yaml
import logging
from netmiko import ConnectHandler, NetmikoTimeoutException, NetmikoAuthenticationException

logging.basicConfig(
    filename='netmiko_execution.log',
    level=logging.INFO,
    format='%(asctime)s - %(levelname)s - %(message)s'
)

def deploy_router_config(device_params):
    try:
        logging.info(f"Connecting to router {device_params['host']}...")
        net_connect = ConnectHandler(**device_params)
        net_connect.enable()

        output = net_connect.send_config_set(device_params['config_commands'])
        logging.info(f"Successfully configured {device_params['host']}:\n{output}")

        net_connect.save_config()
        net_connect.disconnect()
    except NetmikoTimeoutException:
        logging.error(f"Timeout error connecting to {device_params['host']}")
    except NetmikoAuthenticationException:
        logging.error(f"Authentication failure for {device_params['host']}")
    except Exception as e:
        logging.error(f"Unexpected error on {device_params['host']}: {str(e)}")
\end{lstlisting}

\caption{Comparative Evaluation: Python/Netmiko vs Ansible}

\section{Challenges, Troubleshooting \& Root Cause Analysis}

A couple of issues came up during the build that are worth documenting, since the fixes shaped parts of the final design.

\subsection{VLAN 99 Management Plane Isolation (L2 Split Post-L3 Conversion)}

\subsubsection{Problem Description}
Right after we converted the distribution uplinks to routed \texttt{/30} interfaces, \textbf{VM-AUTO} (\texttt{10.99.99.100}), sitting on \textbf{SW-CORE}, lost SSH reachability to every distribution switch (\texttt{.11}, \texttt{.12}, \texttt{.13}) and access switch (\texttt{.21}, \texttt{.22}, \texttt{.23}).

\subsubsection{Root Cause Analysis}
The routed uplinks had effectively cut VLAN 99 into \textbf{four separate Layer 2 islands}, one per switch. ARP requests from \texttt{VM-AUTO} for something like \texttt{10.99.99.11} never made it past SW-CORE, because there was no longer a bridged path over the uplink to carry them. On top of that, the access switches were still pointing their default gateway at \texttt{10.99.99.1} (SW-CORE), which they could no longer reach at Layer 2 either.

\begin{lstlisting}[style=console, caption={VLAN 99 Layer 2 Segmentation Diagram}]
       ISLAND 1 (L2)                    ISLAND 2 (L2)
  +---------------------+          +---------------------+
  | VM-AUTO 10.99.99.100|          | SW-D-DEIE 10.99.99.11|
  | SW-Core 10.99.99.1  |--ROUTED--| SW-A-DEIE 10.99.99.21|
  | SW-A-DIS 10.99.99.24| 10.0.10  |                     |
  +---------------------+  /30     +---------------------+
\end{lstlisting}

\subsubsection{How We Fixed It}
\begin{enumerate}
    \item \textbf{Host static routes on SW-CORE}: we added explicit \texttt{/32} routes so management traffic bound for a specific switch would go out the correct \texttt{/30} uplink instead of trying (and failing) to use the local \texttt{/24}:
\begin{lstlisting}[style=ciscostyle]
ip route 10.99.99.11 255.255.255.255 10.0.10.2
ip route 10.99.99.21 255.255.255.255 10.0.10.2
ip route 10.99.99.12 255.255.255.255 10.0.20.2
ip route 10.99.99.22 255.255.255.255 10.0.20.2
ip route 10.99.99.13 255.255.255.255 10.0.30.2
ip route 10.99.99.23 255.255.255.255 10.0.30.2
\end{lstlisting}
    \item \textbf{Return routes on the distribution switches}: added a host route back to \texttt{10.99.99.100} via SW-CORE's point-to-point interface, so replies could find their way home.
    \item \textbf{Re-pointed the access switch gateways}: instead of \texttt{10.99.99.1}, each access switch now points at its own local distribution switch (\texttt{10.99.99.11}, \texttt{.12}, or \texttt{.13}), which it can actually reach at Layer 2.
\end{enumerate}

\subsection{OSPF Adjacency Failure \& ACL Filtering Remediation}

\subsubsection{Problem Description}
OSPF wouldn't come up between \textbf{SW-CORE} and \textbf{R-CORE}, and separately, \textbf{VM-AUTO} started getting "Communication administratively prohibited" back whenever it pinged router interfaces.

\subsubsection{Root Cause Analysis}
Two things, as it turned out:
\begin{enumerate}
    \item \texttt{passive-interface default} on SW-CORE was silently suppressing OSPF Hellos on \texttt{Gi0/1} — we'd forgotten to exempt that interface.
    \item \texttt{ACL-MGMT-IN} on SW-CORE had no explicit \texttt{permit icmp} entries for the transit subnets (\texttt{10.0.0.0/30}, \texttt{10.0.1.0/30}), so the implicit deny at the end was catching pings that should have gone through.
\end{enumerate}

\subsubsection{How We Fixed It}
\begin{enumerate}
    \item Ran \texttt{no passive-interface GigabitEthernet0/1} under \texttt{router ospf 1} on SW-CORE, which let the Hellos through and OSPF formed immediately.
    \item Rebuilt \texttt{ACL-MGMT-IN} to explicitly permit ICMP and SSH across the transit subnets before the implicit deny takes over.
\end{enumerate}

#!/usr/bin/env python3
"""
EE8203 Campus Network Project - Netmiko Router Automation
Configures R-CORE and R-EDGE interfaces, OSPF Area 0, static routes, and NAT overload.
"""
import yaml
import logging
from netmiko import ConnectHandler

logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s')

def load_inventory(filepath="inventory.yaml"):
    with open(filepath, 'r') as f:
        return yaml.safe_load(f)

def run_automation():
    inventory = load_inventory()
    for dev_name, params in inventory['routers'].items():
        logging.info(f"Applying configuration to {dev_name}...")
        try:
            conn = ConnectHandler(**params['connection'])
            conn.enable()
            output = conn.send_config_set(params['config'])
            logging.info(f"Output for {dev_name}:\n{output}")
            conn.save_config()
            conn.disconnect()
        except Exception as e:
            logging.error(f"Failed to configure {dev_name}: {e}")

if __name__ == "__main__":
    run_automation()
\end{lstlisting}
